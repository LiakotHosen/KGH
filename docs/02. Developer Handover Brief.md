# KGH Dental — Developer Handover Brief
Status: DRAFT for client approval, v1 — 2026-09-03

---

## 1. Project Overview

KGH Dental is a new multi-doctor dental chamber (5-6 doctors across specialties). This is a **ground-up build** — no existing website, no final logo, no fixed clinic address yet. The site must be premium, animation-rich, bilingual (English/Bangla), and built so the client's non-technical team can manage almost everything from an admin panel after launch.

**Design/structure inspiration:** odchealthcares.com — follow their *structure* (how appointment booking, department pages, and site organization work), **do not copy their content or exact layout**. KGH Dental's design must look distinct and premium in its own right.

**Reference design mockups:** 3 grey/black/white concept images provided in `Webstie deisgn References/` — follow this visual direction.

**Tech stack (recommended, matching pattern used across this agency's other client builds):**
- Frontend: Next.js (App Router), Tailwind CSS
- Backend/DB: Supabase (Postgres + Auth + Storage) — powers the admin panel and all dynamic content
- Animation: Framer Motion and/or GSAP (ScrollTrigger) for scroll-reveal, glassmorphism, hover, text, and micro animations
- Icons: Lucide (premium/animated variant where possible)
- Hosting/deploy: Vercel (standard for this agency's stack)
- i18n: EN/BN toggle — every page, every string must have both language versions stored and switchable without page reload feel (client requirement: Bangla must NOT read as literal/robotic translation — it must be natural, conversational Bangla)

## 6A. SEO Content Writing Plan (Bilingual — EN + BN)

SEO is a first-class requirement across the entire site, in **both languages**, not just English with Bangla as an afterthought.

**Scope of SEO-optimized copy:**
- Homepage, About, all 7 department pages, all 54 sub-service entries, all 10 blog posts, Doctors page, Contact page — every page gets EN and BN SEO copy
- Each page/section needs: meta title, meta description, H1/H2 structure with target keywords naturally worked in, alt text for images (EN + BN)
- Keyword research to be done **separately for English and Bangla search behavior** — Bangla-speaking patients often search in Banglish/phonetic Bangla or mixed English-Bangla terms (e.g. "রুট ক্যানেল কত দিন লাগে", "best orthodontist Dhaka"), so BN keywords are not just translations of the EN keyword list — they need their own research pass
- Department/sub-service pages: target long-tail, intent-based keywords (e.g. "wisdom tooth removal cost Dhaka" style intent, though price itself is never shown) — why/when/benefit copy format already supports this naturally
- Blog articles (10 at launch, 1500–2000 words each): each targets a specific keyword/topic, written for EN; **client to confirm whether Bangla blog versions are also required** (currently an open item — see Section 9)
- Technical SEO (developer responsibility, not copywriting): clean URL slugs (EN and BN routes if BN gets separate URLs, or a locale-based routing approach), sitemap.xml, robots.txt, structured data/schema markup for a Dental Clinic + individual doctors (Physician schema) + services, fast page-load performance (Core Web Vitals — especially important since the site is animation-heavy, so animations must be optimized/lazy-loaded, not tank performance scores), proper heading hierarchy, image compression/next-gen formats

**Bangla SEO copy must still follow the non-negotiable rule from Section 8:** natural, conversational ভাবানুবাদ — never literal/robotic translation — even while targeting SEO keywords. Keyword placement must not break the natural reading flow.

## 6B. Responsiveness — Mandatory, All Devices

Every single page and component — including the animated hero, mega-menu, mobile hamburger accordion, department accordions, doctor cards, and the appointment booking flow — **must be fully responsive and tested on:**
- Mobile (iOS and Android, various screen widths — small phones to large phones)
- Tablet
- Laptop
- Desktop/large monitor

This is non-negotiable for every page, not just the homepage. Specific call-outs for this project:
- The interactive mega-menu (desktop) and the accordion-style hamburger dropdown (mobile) are two *different* components by design (Section 4) — both need their own responsive/interaction testing, not just a single component that reflows
- Glassmorphism, scroll animation, and hover effects must degrade gracefully on touch devices (no hover-only interactions that become undiscoverable on mobile)
- Booking calendar/time-slot picker must be fully usable with touch input, not just mouse
- Bangla text (which can run longer than English for the same content) must not break layouts — test both languages at every breakpoint

## 7. Admin Panel (Backend) — Full Scope

Everything visible on the frontend must be editable from the admin panel. No hardcoded content beyond structural layout/design.

**Modules:**
1. **Doctors** — CRUD: name, photo, department, credentials, bio, weekly availability, slot interval, active/inactive toggle
2. **Departments/Services** — CRUD department pages; CRUD sub-services within each (name EN/BN, why/when/benefit copy EN/BN, image upload)
3. **Appointments** — view/manage incoming bookings, filter by doctor/date, mark status (pending/confirmed/completed/cancelled)
4. **Gallery** — image upload/manage + Facebook video URL entries, reorderable
5. **Blog** — CRUD blog posts (EN/BN), 10 seeded at launch, SEO fields (meta title/description, slug)
6. **Google Reviews** — manual entry of reviews pulled from Google (client adds them via admin), plus a **QR code** asset displayed on the frontend so visitors can leave a live Google review
7. **Site settings** — clinic address (placeholder until real one is supplied), phone numbers, working hours, social links, logo asset (swappable), language toggle default

**Auth:** Admin panel needs login-gated access (Supabase Auth), not public.
